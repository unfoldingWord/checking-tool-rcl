# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`checking-tool-rcl` is a React component library (RCL = Resource Container Library) that provides the UI for Bible translation checking — reviewing Translation Notes (TN) and Translation Words (TW) against a target-language translation. It's published to npm and consumed by host apps (e.g. translationCore-based tools); it is not a standalone app. Use `yarn`, not `npm` — the repo ships a `yarn.lock`.

## Commands

- Install deps: `yarn`
- Run the styleguide demo (renders the components in `styleguide.config.js` sections): `yarn start`
- Run all tests: `yarn test`
- Run a single test file: `yarn test path/to/file.test.js` (or `yarn test -t "test name"` to filter by name)
- Lint: `yarn lint` / autofix: `yarn lint:fix`
- Format: `yarn format` (Prettier over the whole repo)
- Production build (outputs to `dist/`, UMD bundle via Webpack): `yarn build`
- Dev build with sourcemaps: `yarn build:dev`; watch mode: `yarn watch`
- Build the static styleguide site: `yarn build:sg`

CI (`.github/workflows/main.yml`) just runs `yarn && yarn test` on push/PR.

Publishing: `prepublishOnly` rebuilds `dist/` from scratch before `npm publish`; `postpublish` tags the release as `v$npm_package_version` and pushes the tag. `dist/` is the actual package payload (`main`/`source` in `package.json` point there) — don't hand-edit it, it's generated by webpack from `src/index.js`.

## Architecture

### Entry point and public API

`src/index.js` is the sole public entry point. It exports the `Checker` component plus a grab-bag of helpers/constants re-exported for host apps: `Constants`, `BooksOfTheBible`, `TranslationUtils`, `tnArticleHelpers`/`twArticleHelpers`, and alignment/USFM helpers re-exported from the external `word-aligner-lib` package. When adding something a host app needs to consume, it must be re-exported here — nothing outside `index.js`'s export list is part of the package's public surface.

### The `Checker` component (`src/components/Checker.js`)

This is the top-level orchestrator and the most important file to read first. It is a single large component (no reducer/context) that:
- Takes raw inputs from the host app as props: `checkingData` (TN or TW check data), `glWordsData` (gateway-language article/index data), `targetBible`, `alignedGlBible`, `contextId`, plus host-provided callbacks (`saveCheckingData`, `saveSettings`, `changeTargetVerse`, `getLexiconData`, `translate`, etc.). The host app owns persistence; `Checker` calls back into it rather than persisting anything itself.
- On mount/data-change, flattens `checkingData` via `groupDataHelpers.flattenGroupData` (from `word-aligner-lib`) and builds a navigable index via `parseTnToIndex`/`parseTwToIndex` (`src/helpers/translationHelps/{tnArticleHelpers,twArticleHelpers}.js`), branching on `checkType` (`TRANSLATION_NOTES` vs `TRANSLATION_WORDS`, from `src/common/constants.js`).
- Manages verse selections, verse edits (with alignment updates via `AlignmentHelpers.updateAlignmentsToTargetVerse`), comments, bookmarks/reminders, and tag state — all as local component state, with "temp" (unsaved) vs "current" (saved) value distinctions (`getTempValueFor` vs `getCurrentValueFor`) so users can cancel edits.
- Composes the actual UI from `src/tc_ui_toolkit/*` (GroupMenuComponent for check navigation, `CheckInfoCard`, `ScripturePane` for multi-pane source/target text, `TranslationHelps` sidebar, `VerseCheck` for the main check/select/edit/comment interface) plus `PopoverContainer` from `src/containers`.

Most business logic (parsing group data, selection validation, article lookups, markdown link rewriting) lives in `src/helpers/` and is imported into `Checker.js` as plain functions rather than hooks — keep that pattern when extending it.

### Directory roles

- `src/components/` — top-level exported components (`Checker.js`) and their styleguide docs (`*.md`, rendered by `yarn start`).
- `src/containers/` — thin wrapper components pairing a UI component with local state/props wiring (e.g. `PopoverContainer`, `GroupMenuContainer`).
- `src/tc_ui_toolkit/` — the actual checking UI widget library (ported from translationCore's tc-ui-toolkit): `ScripturePane` (multi-pane Bible viewer with add/remove/expand panes), `VerseCheck` (selection/edit/comment states for a single verse check), `GroupedMenu`, `CheckInfoCard`, `Bookmark`, `FontSelectionMenu`, etc. Each has its own subfolder with `index.js`, styles, and often a `helpers/` subfolder.
- `src/helpers/` — non-UI logic: group data flattening/navigation, TN/TW article parsing and markdown link rewriting (`translationHelps/`), check-area and file helpers, `tsv-groupdata-parser/` for TSV-based group data.
- `src/common/` — shared constants (`constants.js`, `BooksOfTheBible.js`) and font config (`complexScriptFonts.js`).
- `src/utils/translations.js` — misc translation-string utilities, re-exported as `TranslationUtils`.
- `src/__tests__/fixtures/` — shared JSON/USFM fixtures (bibles, checks, lexicon, TA/TN/TW data) used across Jest tests; component-local tests live alongside their component in `__tests__` subfolders (e.g. `src/tc_ui_toolkit/VerseCheck/__tests__`).

### External domain dependencies

Several unfoldingWord packages carry core domain logic and are treated as the source of truth rather than reimplemented here: `word-aligner-lib` (alignment helpers, USFM conversion, verse/selection validation, group-data flattening), `usfm-js` / `uw-tsv-parser` (USFM and TSV parsing), `tc-source-content-updater`, `tsv-groupdata-parser`, `bible-reference-range`, `string-punctuation-tokenizer`, `wordmap-lexer`. When something looks like it should be "verse/alignment/USFM logic," check whether it already exists in `word-aligner-lib` before adding it locally.

### Styling

Material-UI v4 (`@material-ui/core`/`icons`) is the component library; peer dependencies require v4, not v3 or v5. Component-scoped CSS lives next to each component (e.g. `VerseCheck.styles.css`, `ScripturePane.styles.css`) and is loaded via `style-loader`/`css-loader`/`sass-loader` in both webpack configs and the styleguide's webpack config.

## Code style

- ESLint config (`.eslintrc`) extends `eslint:recommended` + `plugin:react/recommended`; notably `no-undef` is only a `warn`, and semicolons are required except at the end of one-line blocks.
- Prettier (`.prettierrc`): no semicolons, single quotes (including JSX), `arrowParens: avoid`. Existing code is inconsistent about semicolons — match the surrounding file rather than one rule everywhere.
- 2-space indentation, LF line endings, final newline (`.editorconfig`).
